# Traçabilité : Overwatch

Règles confirmées par le product owner (OQ-TURN-007, OQ-OVERWATCH-001 à 009). Tests : `packages/core/src/overwatch/overwatch.spec.ts` (O), `turn/turn.spec.ts` (T), `actions/legal-actions.spec.ts` (L), `combat/attack.spec.ts` et `tests/integration/` (I).

| ID | Règle | Implémentation | Test |
|---|---|---|---|
| RULE-OVERWATCH-001 | Placer un personnage en Overwatch coûte 1 PC (`CommandPointService`, événement `COMMAND_POINTS_SPENT`, but `OVERWATCH`), uniquement en phase `OVERWATCH`, avant les activations, dans la limite des PC. Ne consomme aucune action d'activation. Événement `OVERWATCH_PLACED`. | `overwatch/handlers.ts` (`OVERWATCH`, `checkOverwatchPlacement`, `OVERWATCH_COST`) | O placement, refus sans PC, alternance stricte ; L |
| RULE-OVERWATCH-008 | Décisions alternées : `turn.activePlayerId` est le joueur qui décide (gagnant de l'initiative d'abord) ; il place UN SEUL personnage (`OVERWATCH`, la main passe à l'autre joueur, compteur de passes remis à 0) ou passe (`PASS_OVERWATCH`, `OVERWATCH_PASSED`, `turn.overwatchPasses` +1, la main passe à l'autre joueur). Deux passes consécutives : `OVERWATCH_PHASE_ENDED` puis phase ACTIVATION. Un joueur sans PC ou sans personnage éligible peut seulement passer (aucun passage automatique). La relance d'initiative (1 PC) reste possible tant que `turn.overwatchDecisions` vaut 0 (aucun placement ni aucune passe) ; le nouveau gagnant décide alors en premier. | `overwatch/handlers.ts` (`OVERWATCH`, `PASS_OVERWATCH`, `checkPassOverwatch`), `turn/start-turn.ts` (`startTurn`, `beginActivations`), `turn/handlers.ts` (`REROLL_INITIATIVE`), `state/types.ts` (`TurnState.overwatchPasses`, `overwatchDecisions`) | O alternance stricte, ordre de décision, passe puis placement adverse, deux passes, aucun PC ; T phase OVERWATCH, REROLL_INITIATIVE (avant/après décision) ; I phase d'Overwatch alternée |
| RULE-OVERWATCH-009 | Un personnage en Overwatch est traité comme déjà activé (`activated: true`) : non activable (`IN_OVERWATCH`) ; il ne bloque pas la fin du tour ; si plus aucun personnage n'est activable, le tour suivant démarre aussitôt. | `overwatch/handlers.ts`, `turn/handlers.ts` (`checkSelectCharacter`), `turn/start-turn.ts` | T non activable, fin de tour sans bloquer ; L SELECT |
| RULE-OVERWATCH-002 | Déclencheur (a) : un adversaire ENTRE dans la ligne de vue d'un Overwatch pendant son déplacement : le déplacement s'arrête sur cette case (PM payés jusque-là) ; `OVERWATCH_TRIGGERED`. Jamais pour un allié, un mort, ni un overwatcher ayant refusé (RULE-OVERWATCH-010). | `movement/handlers.ts`, `overwatch/trigger.ts` (`findOverwatchers`) | O Déclencheur a ; I |
| RULE-OVERWATCH-010 | Déclencheur (b) : un adversaire DÉJÀ dans la ligne de vue qui tente de se déplacer ou d'agir (`MOVE_CHARACTER`, `ATTACK`, `OPEN_DOOR`, `CLOSE_DOOR`) ouvre la réaction AVANT l'exécution ; la commande est validée à blanc (`DryRng`, aucun tirage de la partie) : une commande invalide n'ouvre aucune réaction. La commande annoncée est mémorisée (`PendingReaction.resume`, `OVERWATCH_TRIGGERED.announced`). | `overwatch/handlers.ts` (intercepteur), `engine/apply-command.ts` (`registerInterceptor`, `dryValidate`, `DryRng`) | O Déclencheur b ; `attack.spec.ts` |
| RULE-OVERWATCH-003 | L'activation adverse est suspendue (`turn.reaction`) : toute autre commande est refusée (`REACTION_PENDING`) jusqu'à la réponse du joueur en Overwatch. | `TurnState.reaction`, `PendingReaction`, `checkCommandGate` | O commandes refusées pendant la réaction |
| RULE-OVERWATCH-004 | Plusieurs personnages en Overwatch voient l'adversaire : réactions successives, le premier dans l'ordre de l'état d'abord (OQ-OVERWATCH-002, OQ-OVERWATCH-007). | `findOverwatchTrigger` | O plusieurs overwatchers |
| RULE-OVERWATCH-005 | L'attaque d'opportunité est OPTIONNELLE : `OVERWATCH_FIRE` (échange d'attaque complet, `checkTargeting`) ou `OVERWATCH_DECLINE`. Événement `OVERWATCH_RESOLVED` (`fired`). | `overwatch/handlers.ts`, `combat/exchange.ts` | O FIRE (touché, manqué, paré), DECLINE |
| RULE-OVERWATCH-011 | Après la réaction, la commande annoncée est rejouée (`executeCommand`) si l'adversaire est vivant ; s'il est tué, son activation se termine sans reprise ; si elle est refusée à la reprise : `OVERWATCH_RESUME_REFUSED` (OQ-OVERWATCH-008). | `overwatch/handlers.ts` (`resumeAnnounced`) | O reprise, cible tuée, reprise refusée |
| RULE-OVERWATCH-006 | Une fois l'attaque d'opportunité RÉALISÉE (FIRE), le personnage n'est plus en Overwatch (`overwatch: false`) et reste non activable ce tour. | `overwatch/handlers.ts` | O FIRE, non activable |
| RULE-OVERWATCH-012 | Refus (DECLINE) : l'Overwatch reste actif mais ne se redéclenche pas contre ce même adversaire pendant son activation courante (`turn.overwatchWaived`, remis à zéro au changement d'activation) ; il réagit de nouveau à l'activation suivante (OQ-OVERWATCH-005, RÉSOLUE). | `overwatch/handlers.ts`, `turn/start-turn.ts` (`turnWithoutActivation`) | O DECLINE |
| RULE-OVERWATCH-013 | Un Overwatch non tiré dure tout le tour et est retiré au refresh du tour suivant, quand les PC sont rendus (OQ-OVERWATCH-006, RÉSOLUE). | `turn/refresh.ts` | O cycle de vie ; I |
| RULE-OVERWATCH-007 | Seul le joueur concerné répond (`NOT_YOUR_REACTION`) ; sans réaction, FIRE/DECLINE sont refusés (`NO_REACTION`). | `overwatch/handlers.ts` | O refus |
| RULE-OVERWATCH-014 | `getLegalActions` : `OVERWATCH` n'est disponible qu'en phase Overwatch, pour le joueur dont c'est le tour de décider, avec au moins 1 PC et un personnage non en Overwatch ; `PASS_OVERWATCH` est disponible pour ce même joueur, même sans PC (raisons françaises : « Impossible : 1 PC requis. », « Impossible : ce n'est pas votre tour de décider. », « Impossible : l'Overwatch se place avant les activations. »…) ; `getReactionOptions` expose la commande annoncée. | `actions/legal-actions.ts` | L |
